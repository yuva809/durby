Technical flow

Saving a picture

  1. BrowserPick a file in the product dialog. It is resized to at most 800 px and 300 KB; transparent areas turn white.
  2. Browser → APIThe product is saved first (POST or PATCH /catalog/products), then the picture with PUT /catalog/products/:id/image (the raw file as the body).
  3. APIChecks catalog.products.edit, the size and the first bytes of the file (WebP, PNG or JPEG), not only the content type.
  4. API, one transactionWrites the bytes to product_images and an audit row catalog.product.updated without the bytes. imageVersion changes.
  5. BrowserReads GET /catalog/products/:id/image with the signed-in token. imageVersion in the address is the cache key.
RoutePermissionAnswers
PUT /catalog/products/:id/imagecatalog.products.editThe product; 400 catalog.product_image_invalid; 413 platform.payload_too_large
GET /catalog/products/:id/imagecatalog.products.readThe file; 404 without one
DELETE /catalog/products/:id/imagecatalog.products.editThe product without picture
  • Product lists carry imageVersion only, never the file.
  • Feature catalog. The table has row-level security like every tenant table.
