Audit log

Every change in an organization, append-only: who did what, when, to which record and where. The viewer is a table with module, branch and date filters, a search, an expandable before/after per row, and CSV export. Code: apps/api/src/platform/audit/, apps/web/components/audit/audit-page.tsx, apps/web/lib/audit/ (filters.ts, present.ts, diff.ts). Spec: docs/platform/audit.md, docs/platform/web-shell.md → Audit log viewer. Decision: ADR 0008. Branch: feature/floor-and-split.

Data

audit_logs   tenant_id, actor (user id | system key), action (registry key), entity_type, entity_id,
             before / after (allow-listed snapshot, JSON), request_id, ip, created_at      append-only, RLS

Snapshots hold only the fields in AUDIT_SNAPSHOT_FIELDS (packages/shared/src/audit.ts): never secrets, notes, guest data or emails. User emails are looked up when the page is read, never stored. The viewer derives everything it shows from these rows.

API

GET /api/v1/audit-logs, platform.audit.read (Owner, Admin). Newest first, cursor pages (default 50, max 200).

  • Row chevron opens the before/after table (changed fields marked), the record id, request id, IP, and "Only this person".
  • Filters in one row, applied as they change and kept in the URL: search, module, record type, action (narrowed to the module and type), branch, from, to; Clear.

  • Below 1024 px each row is a card. Labels: platform.auditPage.* (en, de).

CSV export

  • Fetches every page of the current filters (200 per request) up to the newest 5,000 entries, applies the search, and downloads audit-log-YYYY-MM-DD.csv; a note appears when the export was cut.
  • Columns: When, What, Module, Detail, Record, By, Email, Role, Where, IP, Request id.
  • UTF-8 with a BOM (umlauts, ₹ and € open correctly in Excel); CRLF lines; every cell quoted.
  • Formula injection: cells starting with = + - @, tab or CR get a leading ', so spreadsheets never run them (csvCell).

Known gaps and notes

  • Search covers loaded entries only. Server-side text search over snapshots would need a database index (later).
  • Records without locationId in their snapshot (organization-wide: products, roles, stock items) show "Whole organization" and are not found by the branch filter. Warehouse-level placement (e.g. "Main Warehouse") would need the warehouse id in stock snapshots.
  • The record name is plain text; linking each record type to its page is a follow-up.
  • API e2e tests were not run on the development laptop (no Docker).
