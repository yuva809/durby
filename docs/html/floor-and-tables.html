Floor and tables

Table service steps 1 and 3: dining areas and tables per location, the floor view, orders with tickets, covers, voids, closing, kitchen and bar screens, and the QR menu. Code: apps/api/src/modules/pos/, apps/web/components/pos/, apps/web/components/tables/. Spec: docs/modules/pos.md (Steps 1, 3). Decisions: ADR 0016, ADR 0025, ADR 0026, ADR 0031.

Data model

Location
 ├─ DiningArea        dining_areas        name, sort order (table service area; replaces the free-text area)
 └─ DiningTable       dining_tables       name, seats, shape, colour, area, menu token, archived_at
     └─ PosOrder      pos_orders          one open order per table (partial unique index), number ORD-{YYYY}-{seq:6},
         │                                covers 1–100, opened/closed by user, status open | closed
         ├─ PosKitchenTicket  pos_kitchen_tickets   append-only; sequence per order; kind order | void;
         │                                          station kitchen | bar; direct (ADR 0031)
         │   └─ PosTicketStatusChange  pos_ticket_status_changes   append-only; preparing | ready | served
         └─ PosOrderLine      pos_order_lines       append-only; name, gross unit price and VAT rate
                                                    snapshot; quantity < 0 on voids

PosPrinter / PosPrinterStation / PosPrintJob / PosPrinterCommand   printers and queued jobs (ADR 0032, 0033)

Tables and areas are archived, not deleted, because orders and checks reference them. Orders, tickets, lines and status changes are append-only (rule 7): a correction is a void ticket with negative lines.

Business rules and where they live

Rule Enforced in
One open order per table; first send to a free table races on the partial unique index, the loser retries once migration pos_orders_one_open_per_table_key, orders.service.ts
A send writes one ticket per station (kitchen first), in one transaction orders.service.ts (writeTickets)
Void goes to the station that received the item, even if the category moved orders.service.ts
Products must be orderable at the location (not archived, price rules applied) catalog PricingService, pos.product_unavailable
Prices and VAT are snapshots; later menu edits don't change past orders pos_order_lines columns
Totals: gross; per-rate split net = gross / (1 + rate), rounded to cents order-totals.ts, order-totals.spec.ts
Station processing off: items go straight to the bill (ADR 0031) orders.service.ts (processing)
Ticket status moves: new → preparing → ready → served, only forward ticket-status.ts, ticket-status.spec.ts
Location-limited roles only see their locations AccessService.locationIdsFor

Web

  • Tables page (/tables, components/tables/): areas as tabs, tables with status and look, create, edit, archive, QR code.
  • Floor (/service, floor-page.tsx): tables of the chosen location grouped by area, free or open, refreshed every 30 s; open tables link to the till.
  • Till (/service/[tableId], order-page.tsx): menu with search and categories, cart with notes, Send to kitchen, guests field, order panel (bill, tickets with reprint and serve), Cancel items (void dialog), Close order.
  • Kitchen and bar screens (/kitchen, /bar): tickets by status, one action per move.
  • Printing: kitchen tickets are print-styled pages; on the Android till app, jobs go to the LAN printer queue (ADR 0033).

Known gaps and notes

  • Reservations pre-fill covers from a seated booking (web only); no server-side link yet.
  • A new order's first send can race another waiter's first send; the second one lands on the same order (tested).
  • The full root pnpm test has not been rerun on this branch; an unrelated timing test in tools/virtual-printer fails on the development laptop.
