Push notifications

One push message every morning for owners: how the restaurant did yesterday (ADR 0083), on top of the stored notifications of ADR 0047 (notifications.html). Code: apps/api/src/modules/reports/daily-report.*, apps/api/src/platform/notifications/, apps/web/lib/account/, apps/web/public/sw.js.

Technical flow

Turning it on

  1. Owner's deviceOverview → Turn on (iPhone: first Add to Home Screen). The browser asks for permission.
  2. BrowserRegisters /sw.js and subscribes at its maker's push service with the server's public key (at most 20 s).
  3. Browser → APIPOST /notifications/push/subscribe keeps the address for this person in this organization.

Every morning

  1. Worker, every 5 minutesDailyReportScheduler goes through the organizations, each in its own tenant context. One that fails is logged; the others go on.
  2. WorkerIs the report due? (time set, and the day has ended at every active location)
  3. WorkerFigures from the Overview's own code, so message and screen can't differ.
  4. Worker, one transactionOne row in report_daily_messages (unique per day) and one daily_sales notification per owner. A second worker finds the row taken.
  5. Worker, deliverySigns the message with the private key and sends it to each device, all at once, at most 3 s each. A device that is gone is removed.
  6. DeviceThe service worker shows it; a tap opens the Overview.

Server setup

  1. Your PC, oncenpx web-push generate-vapid-keys. The private key is a secret: not in chat, not in git.
  2. ServerPut WEB_PUSH_PUBLIC_KEY, WEB_PUSH_PRIVATE_KEY and WEB_PUSH_SUBJECT (mailto:…) into /opt/durby/.env, then bin/dc up -d api worker.
  3. Server, once per restaurantbin/dc run --rm worker node dist/cli/reports.js rebuild --org <id>
  4. To try itbin/dc run --rm worker node dist/cli/reports.js daily --org <id>. It answers sent, done (already sent), early, no_orders or off.
  • The worker reaches the internet through the egress network (outgoing only).
  • Changing the keys later drops every device.
  • NOTIFICATION_EMAILS=on in .env would switch notification emails on. Account emails always go.

Known gaps

  • Amounts can show on the lock screen; the settings page says so.
  • The Android till app cannot receive push (it is a WebView). Owners use the browser.
  • After a rollback to a release before this one, an owner's bell shows an error until the newer release is back.
  • With NOTIFICATION_EMAILS=off the Email column in the settings has no effect.
