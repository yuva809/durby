Orders

  • Customers (order_customers): name, code (unique among active), phone, email, address, note. Archived, never deleted. Audit snapshots keep only id, code and archive time (personal data).
  • Sales orders: number SO-YYYY-000001, customer, warehouse (its location is the branch), requested date, delivery address, note, lines of stock items with quantity and unit price, total.
  • Money: line total = quantity × price, rounded half up to cents; total = sum of line totals. Exact decimals in the api, BigInt cents in the web preview.
  • Statuses: draft → confirmed (→ picking → packed → dispatched → delivered in step 3); cancel up to packed. Each move: timeline row (append-only), audit row, row lock.
  • Sale price: new optional field on stock items; fills the price of a new line.
  • Picking (orders.picking.use): the picked quantity per line (short allowed, never more than ordered) books one goods issue GI-… at average cost; refused below zero stock unless the branch allows it. The order is then packed.
  • Delivery (orders.delivery.use): dispatch with driver, phone and vehicle; delivered with who received it; came back with a reason, which books a restock RS-… at the cost the goods left at. A cancel after picking restocks too.
Order keys are checked at the order's branch: a manager limited to one branch sees and changes only that branch's orders. Staff can read orders and customers but not change them.

API

GET    /api/v1/orders/customers            orders.customers.read
POST   /api/v1/orders/customers            orders.customers.create
PATCH  /api/v1/orders/customers/:id        orders.customers.edit
GET    /api/v1/orders?status=&locationId=&customerId=&from=&to=&limit=&cursor=
GET    /api/v1/orders/:id                  orders.orders.read
POST   /api/v1/orders                      orders.orders.create   { customerId, warehouseId, lines[], confirm? }
PATCH  /api/v1/orders/:id                  orders.orders.edit     drafts only
POST   /api/v1/orders/:id/confirm          orders.orders.edit
POST   /api/v1/orders/:id/cancel           orders.orders.edit     { reason? }
POST   /api/v1/orders/:id/start-picking    orders.picking.use
POST   /api/v1/orders/:id/pick             orders.picking.use     { lines: [{ lineId, quantity }] }
POST   /api/v1/orders/:id/dispatch         orders.delivery.use    { driverName?, driverPhone?, vehicle?, note? }
POST   /api/v1/orders/:id/deliver          orders.delivery.use    { note? }
POST   /api/v1/orders/:id/return           orders.delivery.use    { note? }

All writes need an Idempotency-Key; creates and status moves complete it in the business transaction.
