CRUD permission keys

Business entities guard writes with separate create, edit and delete keys instead of one *.manage key, and Add Staff shows them as View / Create / Edit / Delete columns. Code: packages/shared/src/permissions.ts, apps/api/src/platform/rbac/access.ts, module controllers, apps/web/components/team/staff-dialog.tsx, apps/web/lib/team/matrix.ts. Spec: docs/platform/rbac.md. Decision: ADR 0037 (with ADR 0007, 0023). Branch: feature/crud-permissions.

Reads keep their .read key. Platform keys and action keys (pos.orders.take, inventory.stock.receive, inventory.stock.produce, …) are unchanged. Every system role states grant or deny for each new key, so the typecheck forces the decision: admin and manager keep what manage gave them (managers still have no inventory.items.*), staff and operational roles get none, owner holds all keys.

The guard checks the key for some location; location-scoped services check it again at the entity's location. Each route's key is written next to it in its controller.

Resolution and stored data

stored role keys / member grants / member denies
        │  expandLegacyKeys(): 'pos.tables.manage' → pos.tables.create, .edit, .delete
        ▼
effective keys = role keys ∪ grants − denies       (access.ts; system roles from SYSTEM_ROLE_GRANTS)
  • No migration: custom roles and member overrides that store a *.manage key keep working (expand/contract, ADR 0004). A later release rewrites rows and removes the aliases.
  • New writes can't use a retired key: the team and roles APIs answer rbac.permission_unknown.
  • Granting rules unchanged: a member can give or take only keys they hold (ADR 0007 §6, ADR 0023 §2).

Web: Add Staff matrix

  • Header row Module · View · Create · Edit · Delete. One row per area (crudRow in lib/team/matrix.ts); a cell is blank where the key doesn't exist.
  • Other keys of the area (for example "Take orders") are listed under its row; areas with no create/edit/delete key are listed as before.
  • The box in front of a row ticks or clears the whole area and shows a dash when only part is ticked. It changes only keys the signed-in user holds; others stay locked.
  • "Changed from the role" dot per cell; Role defaults, Select all, Clear; grants and denies are computed against the role (overridesOf).
  • Labels: platform.team.dialog.column.*, platform.team.dialog.wholeArea (en, de).
