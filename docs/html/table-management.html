How it works

Tickets and lines are append-only, so an item can never be rewritten to another order. Instead each ticket has placement rows that say which order it is on; the latest one counts.

pos_orders            the order, its table and number
 └─ pos_kitchen_tickets       written once, keep the order they were sent on
     ├─ pos_order_lines       written once (a void is a negative line)
     └─ pos_ticket_placements which order the ticket is on NOW (latest row wins)
  • A first placement is written by a database trigger with every ticket.
  • Every read of an order goes through the latest placement (ticket-placements.ts).
  • Bills, voids and discounts name the order the line is on now. The check is in the services, under the order's lock.

Technical flow

Move

  1. Till → APIPOST /pos/orders/:id/move { tableId }
  2. APILocks the order. The table must be free, in service and at the same location.
  3. APIChanges only the order's table. No ticket, no kitchen print. Audit pos.order.moved.

Merge

  1. Till → APIPOST /pos/orders/:id/merge { orderId }: the path is the source, the body the target.
  2. APIBoth open, same location; the source has no billed items and no discount.
  3. API, one transactionOne placement per source ticket into the target; the source closes and its table is free. Audit pos.order.merged.
  4. After itThe target keeps its number and can be billed, voided, discounted and transferred as a whole.

Transfer

  1. Till → APIPOST /pos/orders/:id/transfer { tableId, lines }
  2. APIOnly unbilled, undiscounted portions; the table must be free.
  3. API, one transactionA void ticket on the source and a sale ticket on a new order at the table, at the price they were sold at, with the same seat.
  4. KitchenBoth print: the items are made for the new table.

Known gaps

  • Ticket numbers are per order, so a merged ticket keeps its old number in the target.
  • A transfer to an open order is not offered; that is a merge.
  • In reports, two merged tables still count as two orders.
  • Other devices see a move at their next refresh; there is no live hint for it yet.
