How it works

Till (order page) ── Split bill ──► dialog
   ├─ By item     pick portions per line (− / + / All)   ─► POST /pos/bills { orderIds:[order], items:[{orderLineId, quantity}] }
   ├─ Equally     n guests (2–20)                         ─► POST /pos/bills { orderIds:[order], shares:n }
   └─ Join tables other open orders of the location       ─► POST /pos/bills { orderIds:[order, …others] }
                                                              │
                         bill (single | equal) ◄──────────────┘
                           └─ guest checks CHK-YYYY-nnnnnn (one, or one per share) ─► first check printed

A bill covers what is still unbilled; items on a bill that is not cancelled count as billed (billedQuantity), so the dialog only offers what is left. Cancelling a bill (with pos.bills.cancel) frees its items again.

Web: the split dialog

  • Three choices as large buttons (radio group): By item, Equally, Join tables, each with a one-line hint.
  • By item: each unbilled line with its unit price and how many are left; −, count, + and All (44 px targets); Select all / Clear; footer "N items on this bill · total". Nothing picked → "Tap + on at least one item." (nothing sent).
  • Equally: one tap for 2–6 (starts at the table's guests), −/+ up to 20; "About €X each" and "N checks for €Y", plus "Some pay a cent more" when needed.
  • Join tables: other open tables with order number and amount; footer "N tables on one bill · combined total".
  • Button text says the result: "Create bill", "Create 3 checks". API errors show in the dialog once (FormDialog).
  • Labels: pos.split.* (en, de). FormDialog gained submitLabel and wide.

Floor plan fix: tables went back after a refresh

Cause. TablesService.update skips the write when the audit snapshot before and after is the same (a no-op). floorX/floorY had been added to the product snapshot list instead of dining_table's, so a move that changed only the position looked like a no-op: the api answered 200 and saved nothing. The screen kept the table where it was dropped until a reload.

Fix. The fields are in AUDIT_SNAPSHOT_FIELDS.dining_table (with audit labels). A failed move now puts the table back and shows the error instead of failing silently.

Known gaps and notes

  • The equal-split preview is an approximation ("about"): the api splits per VAT rate, so a share can differ by a cent from total ÷ shares.
  • Splitting the same order into named seats ("seat 1, seat 2") is not built: by item creates one bill at a time.
  • API e2e tests were not run on the development laptop (no Docker).
